# SI Grid Monitor V1.0.0 release-candidate status

## Scope

V1.0.0 supports live-power Modes A/B/C only. Active Mode D conversion, runtime,
entities and dashboard presentation have been removed. Legacy Mode D identifiers
remain only where required to recognize old entries and display immutable
historical `counter_derived` provenance.

## Upgrade behavior

- A/B/C entries retain config-entry IDs, entity unique-ID formulas, source epochs,
  checkpoints and schema-6 archives.
- A Mode D entry is detected before runtime construction. No Wh/kWh state is read
  as power and no archive is opened or mutated.
- Home Assistant receives a persistent repair/configuration notice.
- Explicit reconfiguration to A/B/C keeps the same entry ID/archive namespace and
  creates a new epoch when live processing resumes. The entry `unique_id` moves
  to the canonical new source identity only after a cross-entry duplicate check;
  old source epochs and rows are not merged or relabeled.
- Disabled Mode D entries can be unloaded, reloaded, retried after failed setup,
  or removed without dereferencing an absent runtime. Removal still retains the
  archive unless fresh explicit deletion authorization is present.
- Other supported entries continue to start independently.

## Automated versus manual acceptance

Automated checks cover the engine, tariffs, archive schema/migration, lifecycle,
duplicate-source rejection, disabled-entry unload/retry, genuine V0.9.6 schema-6
Mode D preservation, dashboard models, frontend interactions and responsive
layouts. Exact totals are recorded in the PR report after final CI.

Still manual: clean HACS install, V0.9.6 A/B/C upgrade, legacy Mode D notice and
reconfiguration in real HA, restart/reload, Android Companion rendering,
multi-meter switching, live source loss/recovery and archive backup/restore.

CI success alone does not make the release stable. V1.0 remains a release
candidate until the manual checklist is completed.
