# V1.0.3 retrospective audit and remediation matrix

This matrix records the independent review and focused remediation of draft PR
#19 from final-hardening starting head
`71e53eaeb1c74d08eff00536c6fb2c8f549b582a`. It
distinguishes code evidence from operational acceptance. The frozen
`SPECIFICATION.md` was not changed.

## Reproduction evidence before correction

The final-hardening tests were first run against `71e53ea`. They failed in the
following concrete ways before implementation:

1. A real `FixedQuarterEngine` plus real sensor/binary entity readers and the
   real `PublishingController` retained `(61, available=True)` for CAN ADD, MUST
   REDUCE and instantaneous forecast after source reports stopped. The expected
   result was `(61, available=False)` alongside unavailable projected exceedance
   and `input_stale=true`.
2. Under Automation Priority, MUST REDUCE `3.000 → 2.000 kW` published after 25
   seconds even though the required conservative evidence window is 30 seconds.
3. A 3,600-second valid/unavailable one-second source flap emitted recovery
   transitions repeatedly rather than retaining the first fail-closed unknown.
4. A persistent authoritative reader exception left the last public advice
   available indefinitely because no fail-closed entity callback existed.

The tests were retained as regressions. An initial correction also failed the
23/24/25-hour storage benchmark because it emitted nonzero improvements every
30 seconds (approximately 1.35–1.39 GB/year in the synthetic planning model).
That implementation was rejected. The final policy uses 30 seconds as an
eligibility gate while retaining normal cadence and now projects 0.774–0.790
GB/year. This is still not physical Recorder/InfluxDB evidence.

## Independent safety-path review

- `SIGridSensor.available` checks the publication-fault latch before every other
  branch. Source mode, tariff-only and immutable archived values are explicitly
  separated from live advice. Every member of `LIVE_ADVICE_SENSOR_KEYS` requires
  available, non-stale, known instantaneous input, a usable contract and a
  non-null numeric result. Static contractual keys cannot bypass that branch.
- Current/import/export power retain their existing `requires_fresh_input`
  guard. Mode C export and quarter-export remain unavailable through
  `export_known`, so unknown export is not exposed as measured zero.
- `SIGridBinarySensor.available` makes projected exceedance unavailable on stale,
  unavailable or unknown instantaneous input. An already-true unrecoverable
  quarter remains proven from accumulated import; a false value becomes unknown
  during a gap because recoverability can no longer be proven.
- The publication controller prioritizes unavailable transitions over cadence,
  clears pending optimistic timers on loss/worsening/non-monotonic time, and
  stability-debounces recovery. A successful HA callback advances the cursor
  before optional diagnostic bookkeeping, preventing duplicate writes.
- No schema, unique ID, import-only integration, tariff, contract, archive row,
  production configuration or production database path changed in this work.

## Decision boundary

Code-level readiness requires the complete Python, Node, Playwright, Ruff,
compileall, hassfest, HACS, and GitHub Actions checks to pass on the remediation
head. Production release remains **conditional** until an isolated real Home
Assistant/InfluxDB storage measurement and Android Companion acceptance are
recorded. A synthetic CI projection is not proof of the combined 1 GB/year
physical target.

Current recommendation: **code CONDITIONAL GO after all checks pass; storage
CONDITIONAL GO for the synthetic planning model only; production NO-GO until
real Home Assistant/Android and physical Recorder + InfluxDB acceptance is
recorded.** Temporary production exclusions remain an operator-controlled
decision and are not changed by this PR.
