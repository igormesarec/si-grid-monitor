# V1.0.6 targeted source-health audit

| Area | Baseline finding | V1.0.6 extension |
|---|---|---|
| Runtime | Live availability/staleness affected current output but had no durable event history | Stable transition state machine with last-valid and detected timestamps |
| Engine | Authoritative quarter coverage/gap calculation already existed | Unchanged; incident duration is never substituted for gap seconds |
| Archive | Schema 7 preserved quarters, epochs, checkpoints, reconstruction and contract audits | Atomic additive schema 8 incident table and bounded indexes |
| History/analysis | Validity helpers and missing/pre-monitoring rules already existed | Reused for separate quarter completeness and time coverage reports |
| Dashboard API | Entry-scoped executor-backed history commands existed | Added bounded source-health, quality and admin CSV commands |
| Frontend | History/Today drill-down existed; smoothing could visually bridge a short explicit outage | Added Source Health, incident evidence and explicit-interruption trace clipping |
| Localization | Shared English/Slovenian keyed translations existed | Added bilingual diagnostic states, reasons, filters and accessibility labels |
| Publishing | Storage Optimized policy already bounded HA state events | Unchanged; diagnostics write only on source-health transitions |

## Confirmed baseline gaps

- No durable source-health transition history.
- No incident-to-quarter explanatory correlation.
- No reusable report separating complete-quarter percentage from measured-time coverage.
- No bounded incident/incomplete-quarter diagnostic export.
- An explicit source-unavailable observation could occur before the frontend's
  60-second sample freshness line ended.

## Non-goals retained

No external SolarEdge polling, causal hardware diagnosis, high-frequency raw
sample archive, historical outage invention, predictive V1.1 model, load control
or change to the contractual calculation was introduced.
