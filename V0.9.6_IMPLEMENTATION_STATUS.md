# SI Grid Monitor V0.9.6 implementation status

> **Historical release record.** Mode D details below describe the experimental
> V0.9.6 implementation and are not current V1.0 capabilities.

V0.9.6 is a focused Mode D cumulative-counter hotfix. It does not change the
SQLite schema, historical rows, tariff methodology, entity unique IDs or Modes
A/B/C.

| Area | Status | Evidence / limitation |
|---|---|---|
| Quantized fast reports | Implemented | Short reports accumulate against the prior baseline; actual delta is retained |
| Minimum observation time | Implemented | Configurable 1–900 seconds; default 30 seconds |
| Physical plausibility guard | Implemented | Configurable 0.1–10,000 kW; default 100 kW |
| Mode D Options | Implemented | Both policy values are Mode D-only, persist through reload and configure the converter |
| Rejected anomalies | Implemented | Excluded from engine; incomplete gap plus schema-6 provenance diagnostics |
| Unaligned counter windows | Conservative | Energy is conserved, but every quarter touched by a boundary-straddling interval is incomplete |
| Mode D power semantics | Implemented | Derived entities and chart explicitly report interval averages and timestamps |
| Mode D forecasts | Truthfully unavailable | No instantaneous or sustained forecast is inferred from interval-average counter data |
| Counter chart | Implemented | Accepted evidenced segments only; gaps remain disconnected |
| Cumulative-energy chart | Implemented | Uses accepted intervals and authoritative current imported energy |
| Net counter validation | Implemented | Bidirectional net requires state class `total`; direction remains configurable |
| Data compatibility | Preserved | Schema 6, existing archives, checkpoints, namespaces and unique IDs unchanged |
| Numeric presentation | Implemented | kW/kWh display uses three decimals; internal/archive precision remains unchanged |
| TODAY live selection | Implemented | Defaults to live, preserves explicit archive selection on refresh, and provides Current / Live |
| Real Home Assistant/Android acceptance | Pending | Automated tests do not prove actual meter cadence or Companion rendering |

The reported failure mechanism is covered by a regression fixture: a 0.01 kWh
quantized step following a subsecond report would imply approximately 402 kW if
the newest report replaced the baseline. The converter now waits for the full
30-second evidenced span and derives 1.2 kW while retaining exactly 0.01 kWh.

An above-limit discontinuity is rejected rather than clamped. Clamping would
invent a power shape and alter measured energy. The resulting interval remains
incomplete and cannot create a confirmed contractual exceedance. Recovery starts
from a fresh baseline.

The unaligned-cadence fixture reports every 30 seconds at `:17`/`:47` across
four consecutive complete quarters. Exact input energy is conserved. Because
all four quarter boundaries are straddled, 4/4 quarters (100%) are deliberately
incomplete; the integration does not invent which side of a boundary received
the counter delta. An aligned 30-second stream remains counter-derived.

Remaining acceptance work requires a real Home Assistant installation and the
actual meter: verify its state class, counter resolution, update timestamps,
normal maximum import/export power, restart restoration, Android chart rendering
and behavior across a real fixed-quarter boundary. The default 100 kW ceiling is
not a physical-capacity claim and should be configured to the specific meter and
connection with suitable allowance for legitimate peaks.
