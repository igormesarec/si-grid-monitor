# SI Grid Monitor V1.0.3 implementation status

Status: **draft release candidate in PR #19; not released or accepted on a real
Home Assistant installation.**

## Implemented

- Existing V1.0.2 schema-7 contracts, audit, Repairs, calendar evidence and
  archive behavior are preserved.
- English/Slovenian installation preference and persistent dashboard override.
- One centralized publishing controller separates one-second calculation from
  Home Assistant entity state publication.
- Explicit publication policy covers every sensor and binary sensor without
  changing entity keys or unique IDs.
- Storage Optimized default, Automation Priority, Custom and Restore Defaults
  OptionsFlow paths in English and Slovenian.
- Immediate unsafe critical activation with a 30-second continuously-safe
  projected-exceedance clear; direction-aware actionable escalation (MUST
  REDUCE increases and CAN ADD decreases); configurable intervals/deadbands;
  no stable-state or wall-clock-attribute heartbeat.
- Reduced dynamic entity attributes plus Home Assistant unrecorded-attribute
  declarations where diagnostic attributes remain useful.
- Authenticated, entry-namespaced Data Publishing & Storage diagnostics with
  bounded one-hour/day/week windows and all-meter aggregation.
- Responsive Contracts status, historical evidence and audit cards; desktop
  tables remain available.
- Tariff Calendar scroll/selection ownership and explicit offsets for the two
  02:00 hours on the 2026 autumn DST transition.

## Storage benchmark

The deterministic test runs complete Europe/Ljubljana civil days for two
meters through real sensor/binary-sensor values, availability and standard plus
integration attributes. The Recorder-like model includes shared attributes,
metadata/timestamp/context fields and three indexes.

| Local day | Seconds / quarters | Rows | SQLite bytes/day | Recorder-like annual | Unverified Influx allowance | Combined with archive |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Spring DST, 29 Mar 2026 | 82,800 / 92 | 4,363 | 864,256 | 329.2 MB | 232.6 MB | 641.8 MB |
| Normal, 2 Apr 2026 | 86,400 / 96 | 4,551 | 856,064 | 312.5 MB | 232.6 MB | 625.0 MB |
| Autumn DST, 25 Oct 2026 | 90,000 / 100 | 4,773 | 962,560 | 337.3 MB | 234.1 MB | 651.4 MB |

InfluxDB is estimated at 140 bytes per emitted event only for planning. CI does
not run InfluxDB 1.x; physical InfluxDB storage and the combined <=1 GB target
remain **unverified** until isolated 24-hour real-instance measurement. These
figures are planning evidence, not physical-storage acceptance.
