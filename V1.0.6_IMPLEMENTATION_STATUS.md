# SI Grid Monitor V1.0.6 implementation status

Status: **code-complete candidate; real Home Assistant acceptance pending**.

## Implemented

- Atomic, additive SQLite schema-7 to schema-8 migration.
- Per-meter transition-only source-health persistence and restart uncertainty.
- Runtime states for healthy, stale, unavailable, invalid/missing sources,
  Mode-B timestamp mismatch, configuration transition and lifecycle boundaries.
- Source Health dashboard tab, bounded filters/pagination, bilingual labels,
  recurring descriptive patterns and affected-quarter navigation.
- Separate quarter-completeness and measurement-time-coverage reporting.
- Historical quarter incident evidence without equating it to stored gap seconds.
- Admin-only bounded CSV exports for incidents, daily quality and incomplete rows.
- Explicit interruption clipping of the frontend smoothing trace.
- Ordered, timestamp-preserving transition persistence while executor writes are
  blocked, with three bounded attempts per drain pass and no state collapse.
- Complete filtered-range SQLite summary aggregates beyond the visible 200-row
  page, plus complete paged incident CSV export up to an explicit 10,000-row cap.
- Post-recovery interruption windows that keep a brief observed outage visible
  even when recovery occurs within the 60-second sample-validity allowance.

## Data safety

Schema 8 adds only `source_health_incidents` and indexes. Existing quarters,
checkpoints, source epochs, reconstruction revisions, contract audit rows,
targets, tariff provenance and entity identities are not rewritten. The source
health report is read-only except for runtime transition evidence.

## Known limitations

- Exact incident timing before V1.0.6 was not recorded and is unavailable.
- Detection time can follow the physical failure; it is observation evidence.
- Open/restart-spanning intervals retain unknown exact duration.
- Pattern grouping is descriptive and does not identify causes.
- Manual HA/Android testing with real source outages and restarts is pending.

## Event-storage benchmark

A local schema-8 SQLite benchmark (one meter, one transition per row) measured a
122,880-byte empty/healthy database baseline, 294,912 bytes at 365 transitions,
1,220,608 bytes at 2,190 transitions and 19,091,456 bytes at 36,500 transitions.
That is roughly 0.5 KiB per transition at scale, including indexes. A short daily
outage normally creates two transitions; pathological repeated reports in one
unchanged state still create one interval, as covered by a 1,000-report dedupe
regression. This is planning evidence, not a guarantee for every filesystem.
