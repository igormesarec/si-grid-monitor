# V1.0.4 Home Assistant statistics audit

Baseline: merged V1.0.3 (`3d6b394`). This audit is source- and test-based; the
native cleanup procedure remains pending on a backed-up Home Assistant instance.

| Finding | Current behavior | Historical behavior | Risk | Resolution | Evidence |
|---|---|---|---|---|---|
| Current-quarter imported energy | `energy`, `kWh`, no state class; resets every quarter | `total` from V0.1 through V1.0.2 | Retained Recorder metadata reports a state-class mismatch | Keep no state class; administrator reviews/deletes only the obsolete native statistics series | Git history and boundary-publication regression |
| Current-quarter exported energy | Same, but unavailable when export is unknown | `total` from V0.1 through V1.0.2 | Same warning; Mode C must not become measured zero | Keep no state class and preserve export capability gating | Entity metadata/Mode C regression |
| Current/import/export power | `power`, `kW`, `measurement` | Same across audited V0.9–V1.0.3 versions | Useful measurement statistics when Recorder includes them | Preserve | Metadata regression and source history |
| Rolling/smoothed/current averages | `power`, `kW`, `measurement` | Stable in audited releases | Valid sampled/interval power series; not energy totals | Preserve | Sensor descriptions and full regression suite |
| Completed-quarter demand | `power`, `kW`, `measurement` | Stable | One time-aligned 15-minute average per completed interval | Preserve; schema-7 archive remains authoritative | Completion-event and archive tests |
| Remaining quarter budget | `energy`, `kWh`, no state class | No statistical total claim | A changing budget is not accumulated consumption | Preserve | Sensor metadata |
| Contract targets and forecasts | Units retained; no energy-total state class | Stable | Must not be interpreted as consumption | Preserve | Sensor metadata |
| Entity identity | Unique ID remains `<entry_id>_<description_key>` | Same keys and identity model | Recreating IDs would orphan or duplicate history | No rename or entity recreation | Identity regression |
| Recorder exclusion | Stops new recording, not retained statistics metadata | Existing series can remain indefinitely | Warning can remain after exclusion | Document native Statistics-tool review | Official HA documentation |
| SI Grid Monitor archive | Schema 7, independent SQLite store | Schema upgrades preserve rows | Recorder cleanup could be confused with contractual archive deletion | No archive migration or mutation | Archive regression/full suite |

## Metadata migration matrix

| Entity key/group | Previous state class | V1.0.3/V1.0.4 | Reset behavior | Recommended handling |
|---|---|---|---|---|
| `quarter_import_kwh_so_far` | `total` | none | Canonical 15-minute reset | Review/delete obsolete HA statistics only if not needed; retain entity/archive |
| `quarter_export_kwh_so_far` | `total` | none | Canonical 15-minute reset | Same; remains unavailable when export is unknown |
| `current_power`, `import_power`, `export_power` | `measurement` | `measurement` | none | Preserve useful power statistics |
| rolling/smoothed/current power averages | `measurement` | `measurement` | window/quarter changes, not energy accumulation | Preserve sampled power statistics |
| completed-quarter demand/average | `measurement` | `measurement` | replaced once per completed quarter | Preserve fixed-interval power observations |
| `quarter_budget_remaining_kwh` | none | none | recalculated during each quarter | No long-term statistics |
| power targets, advice and forecast kW | none | none | recalculated | No long-term statistics |

## Decision

Option A (no state class) remains correct. Option B is rejected for the current
entity identities: under the default 180-second energy publication cadence, the
last public value before a reset can be lower than the exact completed-quarter
archive value. Neither `total` nor `total_increasing` can reconstruct the omitted
energy safely.

No integration RepairsFlow was added. Home Assistant already creates the native
statistics issue and provides the only supported review/delete workflow; a
second issue would be duplicate guidance and cannot make deletion reversible.

## Affected identities

The exact entity prefix is assigned by Home Assistant and can differ by meter.
Confirmed examples include
`sensor.main_grid_2_current_quarter_imported_energy` and
`sensor.si_grid_monitor_sensor_solaredge_m1_ac_power_current_quarter_imported_energy`.
The corresponding exported-energy IDs can have the same retained metadata when
the source supports export. Administrators must identify the exact statistics
ID in Home Assistant's Statistics tool; V1.0.4 does not guess, rename or purge it.
